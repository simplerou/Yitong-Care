## 1. 项目定位与范围

颐养通从面向社区居民的养老咨询门户，调整为面向养老院工作人员的智能照护协作平台。平台围绕老人档案、照护任务、异常处理与交接班组织工作，六个 Agent 提供知识查询、风险提示和记录草稿辅助。

本期按单个养老院开展建设，不建设多机构 SaaS 管理后台。管理员只设计一种角色，允许配置多个独立管理员账号；不按“系统管理员、院长、护理主管”等继续拆分管理权限。工作人员同样暂为一种角色，岗位可作为人员资料，不直接产生额外权限。

老人是平台中的照护对象，不等同于登录账号。工作人员代老人咨询时必须区分操作人和照护对象，不能把工作人员的年龄、病史当成老人的资料。老人和家属登录端暂不纳入本期。

本文件替代 v0.1 的社区场景需求基线。此前原型、优化记录和评测报告保留为历史证据，不能据此认为养老院新增业务已经实现。

## 2. 现有能力与新增需求

| 模块 | 当前基线 | 养老院升级要求 |
| --- | --- | --- |
| 注册登录、管理员权限 | 已有基础实现；实际数据库状态取决于本机迁移 | 增加工作人员准入、停用及服务端权限校验 |
| 六个 Agent | 已有基础流程、领域规则与会话；不是经过完整业务验收的临床系统 | 支持授权老人上下文、本院制度、人工确认草稿 |
| 知识库与 RAG | 已有解析、切块、向量入库、混合检索、引用与按需联网 | 增加资料范围、版本、适用场景、审核状态 |
| 私人会话 | 已有按账号归属隔离 | 保留；关联老人需新增明确绑定与权限校验 |
| 首页今日守护 | 普通用户为浏览器本地提醒，管理员有演示提醒 | 升级为数据库照护任务，不自动迁移成正式医护任务 |
| 最近对话 | 已读取当前账号六个 Agent 的会话 | 保留，不展示其他人员私人会话 |
| 老人档案、床位、任务、异常、交接班 | 尚未实现 | 本次规划新增 |
| 健康分、助餐、部分服务记录 | 存在原型演示内容 | 不能当作老人真实记录或正式统计 |

## 3. 角色与权限

| 能力 | 管理员（可有多个账号） | 工作人员 |
| --- | --- | --- |
| 机构基础资料、房间床位、人员分配 | 管理 | 查看与职责相关的信息 |
| 老人档案 | 按院内授权管理 | 查看负责老人；登记允许维护的照护信息 |
| 照护任务 | 创建、分配、调整、检查 | 查看并执行分配给自己的任务 |
| 异常事件 | 分派、跟进、审核关闭 | 登记负责老人的异常、补充处理记录 |
| 交接班 | 查看、协调、追踪未接收事项 | 提交本班记录，接收分配给自己的交接 |
| 六个 Agent | 使用 | 使用 |
| 知识库与 RAG 管理 | 管理 | 不显示入口，接口拒绝访问 |
| 私人咨询会话 | 仅本人 | 仅本人 |
| 业务统计 | 本院管理视图 | 个人任务视图 |

管理员角色不自动拥有读取所有私人聊天的权限。需要共享的照护记录通过独立业务模块保存、授权，不依靠公开私人会话实现协作。

现有公开注册只产生普通账号，不因注册获得老人档案访问权限。升级后工作人员须由管理员创建或审核加入本院；未经审核的账号只能停留在待开通状态。此准入流程尚待实现，不能把现有公开注册当作员工身份验证。

## 4. 功能需求与验收

以下 NH-* 编号为养老院升级需求，均属待实现目标；不继续沿用旧社区原型的 FR-* 验收含义。

| 编号 | 优先级 | 功能与验收要求 |
| --- | --- | --- |
| NH-01 | P0 | 同一管理员角色可有多个账号，操作记录区分操作者；多个管理员登录无需共用账号 |
| NH-02 | P0 | 工作人员经管理员开通、关联负责老人；越权直接调用接口应被拒绝；停用后现有会话凭证也不得继续访问 |
| NH-03 | P0 | 维护楼栋/楼层/房间/床位及状态；同一床位不能同时分配两位在住老人，调床保留历史 |
| NH-04 | P0 | 建立老人档案：姓名、出生日期或年龄来源、床位、联系人、过敏、慢病、饮食禁忌、行动沟通情况、照护安排；变更记录来源、时间、操作者 |
| NH-05 | P0 | 照护任务具有对象、负责人、计划时间、状态、执行记录；支持测量、巡房、进食协助等类型。用药任务仅依据已登记并确认的医嘱，不由 Agent 自动创建 |
| NH-06 | P0 | 任务完成、无法完成与异常上报留痕；不允许客户端冒充执行人；并发提交不重复完成任务 |
| NH-07 | P0 | 健康测量保留数值、单位、测量时间、登记人和更正记录；异常提示与人工处理记录分开保存 |
| NH-08 | P0 | 异常事件包括发生时间、对象、情况、紧急程度、处理人、处理经过和结果；待处理→处理中→待复核→已关闭，关闭需管理员确认 |
| NH-09 | P1 | 交接班列出未完成任务、异常和待跟进事项；提交、接收分别记录人员与时间；未确认草稿不算正式交接 |
| NH-10 | P1 | 六个 Agent 接收服务端授权的老人资料；界面持续显示当前老人，切换对象后开启新对象上下文，不能复用上一位老人的个人条件 |
| NH-11 | P1 | Agent 生成记录、交接、照护建议草稿后，工作人员可核对修改并提交；模型不能直接更改档案、医嘱、任务或关闭异常 |
| NH-12 | P1 | 知识资料区分公共参考和本院制度；具备机构、版本、来源、审核状态、适用范围；未经审核的本院制度不进入正式业务检索 |
| NH-13 | P1 | 首页按角色展示本人的任务和真实最近对话；管理员可查看本院汇总，缺失数据显示未记录，不生成虚构健康分或入住率 |
| NH-14 | P1 | 业务记录按职责授权访问；档案修改、分配、任务执行、异常关闭、交接确认有审计记录 |

### 4.1 核心业务流程

管理员维护房间床位 → 建立老人档案 → 分配工作人员 → 创建照护任务 → 工作人员查看本人任务 → 执行并登记测量/照护情况 → 发现异常时上报 → 管理员分派处理并复核 → 交班人提交待跟进事项 → 接班人确认接收。

Agent 在流程中提供资料查询、信息解释、风险提示和草稿；业务状态变化必须由有权限的人员明确操作。

### 4.2 任务状态

任务按待执行、执行中、已完成、无法完成、已取消管理；逾期为根据计划时间计算的提示，不替代实际状态。无法完成和取消必须填写原因，已完成记录需要更正时保留原始值与更正轨迹。重复任务每次生成独立执行实例，不能用一个勾选状态覆盖多天。

### 4.3 六个 Agent 的新定位

| Agent | 养老院业务场景 | 关键边界 |
| --- | --- | --- |
| 健康管家 | 测量解释、变化整理、需关注事项 | 不自动确诊；不把单次规则分级当医生结论 |
| 用药管家 | 已确认医嘱与药品资料查询、用药风险核对 | 不创建、调整或停用医嘱；给药执行须人工核对登记 |
| 政策顾问 | 机构运营、补贴申报、服务规范，也保留老人待遇咨询 | 区分机构政策与个人待遇、地区与时效，证据不足标明缺项 |
| 膳食营养师 | 本院食谱、禁忌、质地与吞咽情况的配餐参考 | 不替代医嘱或个体化治疗营养方案 |
| 安全守护 | 巡房隐患、跌倒事件记录与处置资料查询 | 不替代急救现场判断，不自动认定事故责任 |
| 心灵陪伴 | 老人情绪观察记录、沟通和活动建议 | 不自动诊断精神疾病，不把危机提示当作已通知工作人员 |

## 5. 数据与权限约束

拟新增机构资料、空间床位、老人档案、联系人、人员分配、照护任务与执行、测量、异常事件与处理、交接班与接收、审计记录等实体。具体表名、字段和迁移将在实施前细化，本轮不执行迁移。

- 先建设单院版本；新业务数据预留机构归属，不宣称已实现跨机构租户隔离。
- 老人档案按稳定 ID 关联，姓名及床号仅作展示，不能作为唯一识别依据。
- 同一老人可由多个经授权工作人员照护；分配变化后及时收回读取和修改权限。
- 私人会话按账号隔离，照护业务按机构、负责关系与角色授权；两种范围不能混用。
- 老人个人资料保存在业务数据库，按最小范围读取，不整库写入公共向量知识库或发送给联网搜索。
- 老人切换、任务编辑、状态变化在服务端重新鉴权；前端隐藏菜单不能替代权限控制。
- 历史测试数据继续留在管理员演示范围；不自动当作真实老人档案、医嘱、照护任务导入。

## 6. 非功能要求与边界

保留 Vue 3、FastAPI、LangGraph、Qwen、MySQL、FAISS 及 BM25 + RRF。机构升级优先解决数据、权限和工作流程，不因更换场景重写检索栈。界面桌面优先，兼顾护理人员移动查阅、键盘操作、大字号及清晰错误提示。

任务和记录提交需具备幂等、并发冲突提示、异常恢复；操作成功必须代表服务端持久化成功。模型不可用时仍能登记任务、异常与交接。性能指标在确定试点数据量后测量，不沿用原型首字 2 秒或 SSE 指标作为当前已达成结论。

本期不建设：多养老院运营后台、细分管理角色、家属端、收费结算、硬件自动采集、自动急救调度、自动处方、自动诊断、正式人工坐席。短信验证、登录限流、账号恢复、备份和部署安排列入试点前准备，部署配置最后补充。

## 7. 验收场景

以一位虚构测试老人和两个工作人员账号完成：分配老人→领取测量任务→登记结果→上报异常→管理员跟进复核→交接提交→另一工作人员接收。验证未授权人员不能访问该老人档案，不能伪造执行人，不能跨账号读取私人会话；模型超时不妨碍照护记录保存。

多个管理员账号须独立登录并留下各自操作人信息。演示数据与正式数据应能区分；管理员初始化和历史归档规则继续参照《管理员模式与测试数据归档说明》。自动测试通过不等于临床、政策或业务事实已审核。
