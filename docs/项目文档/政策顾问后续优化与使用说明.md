# 政策顾问后续优化与使用说明

更新日期：2026-10-30。本轮按六项顺序完成可运行实现。软件验证与真实政策事实验收分别记录；没有把历史机械通过结果当作新版全量通过。

## 1. 政策结构化信息

入口：知识库 → 文档详情 →「政策结构化信息（人工维护）」。可填写发布机关、文号、地区、类别、适用对象、发布日期、施行日期、失效日期、效力状态、核验来源/日期、修改与替代文号及备注。保存后用于之后的检索和回答，不修改原文或向量，无需重新入库。

未知字段留空，默认效力为 unknown。标记有效、废止或到期必须同时填写核验来源和日期；核验日期不能在未来，失效日期不能早于施行日期。关联按文号保存，允许关联尚未上传的文件，删除被关联文档也不会丢掉文号。

接口：`PUT /api/documents/{document_id}/policy`，完整替换该文件的人工政策标签；`GET /api/documents/{document_id}` 返回 policy_metadata。标签随 SearchHit 和历史引用快照保存。生成、审查均能看到标签，提示必须区分地区、对象、类别与制度衔接；标签不能代替原文数字或今日效力核验。当前不是自动法规关系图、确定性资格计算器，也不依据标签硬过滤未标注文件，避免历史文档全部消失。自动关系发现、完整表格证据绑定和按行政区划层级过滤仍属于后续扩展。

## 2. 检索上下文

Embedding + BM25 + RRF 排名保持不变。排序取出最终结果后，从同一文档正文中补齐命中位置前后各最多600字符，总窗口不超过4000字符；整体模型原文预算仍为20000字符。金额所在行附近的对象说明、表头、相邻条款有机会一起返回。

正文始终是源文档的连续子串，start/end/chars 与扩展后的原文对应；matched_start/matched_end 保留最初命中区间，context_expanded 标记扩展，heading 保存最近识别到的章节标题作为导航。原文缺失或位置校验失败时保留原命中，不拼造正文。章节标题不伪装成引用正文。最终扩展内容在检索记录与会话快照中保存，回放不会按当前文件重新截取。

无需重切块或重新向量化已有文档。该实现不是完整表格重建：PDF解析已经丢失的列关系无法靠邻近文本恢复；跨页长表、离命中很远的定义仍需进一步处理。

## 3. 多轮咨询条件

入口：政策顾问 →「本次咨询已确认条件（可选）」。手动填写地区、年龄、户籍条件、补贴类别，点击「保存条件」。系统按会话独立保存，刷新仍在，换会话不会借用前一个会话的条件。

这些条件会单独传给问题理解、检索问题和答案生成，并随当次答案快照留存；不再只依靠最近三轮对话。原有最近三轮成功问答仍提供上下文，失败问题不混入历史。不会从助手生成的答案中自动推断个人信息或资格。当前问题明确变更条件时，提示模型优先按本条问题处理；要长期更改已保存条件，请同步修改表单并保存。「清空表单」只清除待保存值，保存后才清除数据库条件。

接口：`PUT /api/agents/policy/conversations/{id}/context`，字段 region、age（0–130或null）、household、benefit。返回会话 context。会话正在生成时拒绝修改，防止一轮中途换条件。更新不改写已保存的历史答案。

## 4. 等待阶段与耗时

后端在进入理解、追问、检索、联网、生成、引用检查、原文一致性检查等节点前保存实际阶段。前端发送问题期间每1.5秒读取阶段，完成或离开页面后停止阶段轮询。刷新后遇到仍在运行的会话，沿用每3秒会话读取，显示已保存阶段。短阶段可能在两次轮询之间完成，因此不是逐帧进度或百分比。

接口：`GET /api/agents/policy/conversations/{id}/turns/{request_id}/progress`，返回 request_id、status、stage；只读，不触发模型。新请求尚未保存时可能404，前端继续等待主请求；主要错误仍由主请求和恢复流程处理。该实现是阶段轮询，未实现SSE、token流式输出或后台持久任务队列。最终答案依旧完整检查后统一显示。

右侧「本次处理耗时」可展开各节点耗时、聊天模型逻辑调用次数、异常次数及返回的token用量。历史回放展示原执行统计，不代表重新执行。llm_ms 已包含在阶段耗时内，不能相加；total_ms 不包括会话写入、HTTP传输或页面渲染。各节点阶段写库耗时计入该阶段。

## 5. 缓存、用量与性能

新增 `TAVILY_CACHE_TTL_SECONDS=300`，可设置0关闭，范围0–600秒。只有成功且有可用正文、没有提取缺页标记的搜索+正文结果会缓存；空结果和异常不缓存。相同问题、官方域名范围、最大条数、凭据与缓存版本共享命中；变更这些设置后不会复用旧键。采用进程内最多64项LRU缓存和单调时钟TTL，重启清空，读写深拷贝，避免一个请求改坏其他请求的来源。

涉及最新、效力、废止、目前、更新、调整或明确年份的问题绕过缓存，工作流判断需要时效时也强制绕过。命中后保留最初 retrieved_at，界面显示短期缓存标记，不把缓存读取时间伪装成新抓取时间。缓存内容仍经现有官方URL限制和正文相关性筛选。未缓存最终回答、本地检索结果或个人条件；缓存不落盘。并发相同未命中请求仍可能各调用一次，当前不是跨进程共享缓存或请求合并器。

聊天接口返回标准 usage.prompt_tokens/completion_tokens 时累计到本轮 metrics；缺失时为null，usage_calls说明返回有效用量的调用覆盖数，可能少于llm_calls。模型JSON格式异常但已返回用量时也计入已返回用量；网络超时等未知用量无法估算。没有硬编码单价或推测账单费用；Embedding、Tavily账单用量未纳入该token统计。

## 6. 回归评测

固定集升级 policy-baseline-1.2：22条（20条本地、2条联网）。新增P17年龄改口、P18地区边界、P19错误金额诱导、P20近似政策类别区分。保留旧用例ID与原文基准，未篡改旧报告。评测报告的代码哈希增加本轮上下文扩展、缓存、指标与政策schema文件。

只校验，不联网、不调用模型：

```bash
python -m scripts.evaluate_policy --validate-only
```

需要本机真实验收时，可只跑新增四项：

```bash
python -m scripts.evaluate_policy --case P17 --case P18 --case P19 --case P20
```

新用例的自动锚点只覆盖部分金额与状态，地区、类别、条件变更仍需按每项人工清单核对。新增四项尚未实际调用Qwen执行，不宣称新版22项业务评测全部通过。
