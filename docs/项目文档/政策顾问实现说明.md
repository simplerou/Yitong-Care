# 政策顾问实现说明

更新日期：2026-10-29。

## 当前能力

政策顾问已接入真实接口；其余五个 Agent 仍为演示。LangGraph 管理请求内的流程，Qwen 负责理解问题及依据资料生成答案，现有 Embedding + BM25 + RRF 服务负责检索。

流程：START → understand → clarify 或 retrieve；retrieve 无命中或问题涉及时效时进入 web_search，有本地命中且无需时效查询则进入 generate → validate；模型认为资料不足时也可进入一次 web_search，再生成并校验。缺少决定性条件时追问；一般概念解释不强制追问。一次请求通常调用聊天模型两次，追问或无命中时一次；实际检索另调用一次 Embedding。工作流没有自主工具循环，也未加入多 Agent 协作。

## 配置与启动

沿用本地 `backend/.env` 中的 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_TIMEOUT_SECONDS` 和 Embedding 配置；禁止提交实际密钥。Qwen 使用 OpenAI 兼容 `/chat/completions`、JSON object 格式、temperature=0。`.env.example` 仅提供空白模板。

新增依赖 `langgraph>=1.2.16,<2`，当前 agent_env 已安装 LangGraph。新环境在 backend 中执行 `python -m pip install -e '.[dev]'`。启动或重启 `python -m uvicorn app.main:app --reload`；前端在 frontend 中运行 `npm run dev`。

`POLICY_KB_IDS=["general"]` 为默认范围。它是后端配置的知识库 ID 数组，前端不能通过聊天请求扩大范围；默认的 general 是现有通用知识库，不代表已建立杭州专用政策库。需要独立政策库时，先创建并完成文档入库，再配置实际知识库 ID。该限制不代替未来的登录/RBAC。

本次未新增数据库结构，无需新迁移；若之前还没有升级至 0004，仍需先执行 `python -m alembic upgrade head`。已有向量和 FAISS 索引可直接复用。

## API 与代码位置

- `GET /api/agents/policy/config`：模型名称、配置状态、后端知识范围，不返回密钥。
- `POST /api/agents/policy/chat`：`question`（1–1000 字），`history`（最多六条，每条仅允许 user/assistant，最多 6000 字）。
- 响应包含 `status`（answered/clarification/insufficient）、`answer`、`citations`、`retrieval_log_id`、`model`、`knowledge_scope`、`steps`。
- `citations` 项包含原始编号 `index` 和 `hit`。编号可能不连续，客户端必须按编号匹配，不能当作数组位置。
- `app/agents/orchestrator.py`：LangGraph 节点、分支及范围传递。
- `app/services/chat/llm.py`：Qwen HTTP 适配、超时与格式错误处理。
- `app/services/chat/prompt_builder.py`：理解与基于原文回答的提示词。
- `frontend/src/components/chat/PolicyChat.vue`：真实政策咨询及引用查看。

请求示例：

```json
{"question":"什么是长期护理保险？","history":[]}
```

后续回答追问时，客户端附带之前的问答历史，让模型补全为独立检索问题。历史不作为政策证据；生成阶段只接收完整问题及本次检索片段。

## 引用与资料不足

最多召回五条，单条上下文最多 4000 字、合计最多 20000 字。模型须按段提供原文编号，后端检查输出结构、编号范围及每段是否带引用，再由程序添加引用标记。非法编号、缺少引用、格式不符或模型判断资料不足时，不展示该草稿，返回资料不足说明。

检查保证引用编号对应传入模型的片段，**不能证明每句结论都被原文支持**。资料相关性、地区适配及事实支持目前依靠模型判断和提示词，仍需人工业务评测。模型也可能漏判追问条件，工作流不等于资格审核系统。

当前没有地区、生效时间、废止状态等结构化政策元数据，已加入 Tavily 官方站点搜索和正文提取，但不自动判定政策现行效力。界面与提示词明确要求谨慎处理有效状态，不应宣称政策最新或用户一定符合资格。原则性文件不足以确定地方补贴金额或办理清单。

## 当前边界与验证

第一版为完整 JSON 回答，尚未做 SSE 流式输出。政策顾问网页现已通过会话接口保存问答及来源快照，刷新后可回放；需迁移0005。原无状态接口仍不保存聊天；尚无 LangGraph checkpointer。首页/服务记录中的演示统计尚未改为真实聊天统计。Qwen 请求超时或格式异常显示明确错误，不回退演示回答。

自动测试使用假模型响应验证图分支、真实 FAISS 检索接入、引用编号、上下文限制、历史传递、HTTP 错误和敏感信息不泄漏。当前执行环境无法连接在线 Qwen，真实模型完整问答仍需在用户网络环境验收；不得把模拟测试视作在线效果验证。

### 问题理解兼容性修复

问题理解按实际路由校验字段：追问分支只要求 clarification，检索分支只要求非空 query；超范围分支允许两者为空或省略。布尔类型仍严格校验，不将字符串自动转换。结构不符时只重试一次，仍失败则返回明确错误；日志仅记录字段路径和错误类型，不记录原始模型输出或用户内容。一般活动建议如“养老活动有哪些”应提示政策顾问的服务范围，不进入检索。引用校验规则保持不变。

### 检索与回答诊断

响应新增 retrieved_hits（实际送入模型的召回片段）、vector_count 和 reason。前端独立展示召回片段及最终引用，模型拒答或格式失败时仍能核对原文。reason 区分 no_vectors、no_hits、model_insufficient、invalid_output、invalid_citations、outside_scope、missing_conditions 和 grounded_answer。模型回答格式/引用异常最多修正一次，仍不合法则明确提示；不能将该失败归因为知识库无资料。生成提示允许政策概览回答原文明确支持的部分，并注明覆盖范围；不因缺少个人条件或未联网核验而直接否定所有解释。该调整不保证模型事实判断正确，仍需业务验收。

正常完整回答通常调用聊天模型两次；结构修正最多使理解和生成各额外调用一次，单轮生成链最多四次；若本地资料不足触发联网后再次生成，整次请求最多六次。前端等待上限调整为 480 秒，以容纳默认超时下的修正请求。

### Tavily 联网搜索（2026-10-29）

在本地 `backend/.env` 的 `TAVILY_API_KEY=""` 中填写 Key，然后重启后端。模板也已添加到 `.env.example`。超时默认 20 秒；最大结果默认 3（可设 1–5）；`TAVILY_INCLUDE_DOMAINS=["gov.cn"]` 控制允许的官方站点域名。无需安装 Tavily SDK，直接复用 HTTPX。

联网触发条件：本地零命中、模型认为本地资料不足，或问题/理解结果要求最新政策、有效性等核验。每次请求最多执行一次联网搜索和一次批量正文提取，不无限循环。前端将本地片段和网页正文分别展示，网页引用附标题、原始 URL、抓取时间及服务明确提供的发布日期；无法获得日期时标记待核实，抓取时间不是发布日期。

搜索和提取通过 Tavily `/search`、`/extract` 完成，只把取到的正文传给 Qwen，不用搜索摘要或 Tavily 直接生成的答案作为证据。返回 URL 再次校验域名、协议和凭据，不接受未请求的提取结果。网页指令仅视为数据，提示词限制其改变系统规则；该约束不能代替事实评测。

Key 缺失、网络失败、额度/鉴权错误或正文提取失败，均有明确状态与提示。本地资料可继续用于带局限说明的回答，不能声称已联网核验；两路均无证据时说明不足。网页不自动写入 MySQL/FAISS，尚无持久化网页缓存或政策效力数据库，不将此实现宣称为完整 CRAG。

`GET /api/agents/policy/config` 新增 web_configured；聊天响应新增 web_sources、web_status、web_warning。web_status 为 not_used/not_configured/success/no_results/error。引用新增 source_type：local 对应 hit，web 对应 web；统一编号，本地编号后接网页编号，客户端按类型打开来源。

只向 Tavily 发送模型整理后的检索问题，不发送聊天历史或本地文档正文。搜索服务自身的计费和额度由 Tavily 账户决定。

填好 Key 后可在 backend 下运行 `python -m scripts.check_tavily` 验证搜索与提取，或提问“杭州市最新养老补贴政策是什么”。本次未填写真实 Key，自动测试使用模拟 Tavily 响应，尚未验证真实搜索效果。

### 联网相关性与时效表述改进

联网正文新增保守的关键词筛选：检查问题的地区和养老主题，问到高龄津贴/养老补贴时要求正文具备对应内容，排除仅含企业补贴的综合经济文件。长正文优先选取主题词集中的 4000 字窗口，再次检查实际传给模型的片段；标题 HTML 转为纯文本。该筛选是确定性启发式，可能漏掉使用别名或跨地区转述的相关页面，不等价于全面语义重排。

当前系统尚无权威的有效性元数据，因此不认证“最新”“现行有效”“仍有效”“未被废止”等结论。生成时检测部分常见无依据时效断言并要求修正一次；最终校验仍不合格的段落被移除，只保留其余有引用的解释，并说明尚不能确认当前效力；若全部段落均被拦截，返回 unsupported_validity_claim 并保留检索原文。不得从未搜到调整/废止文件推导政策仍有效。

此检测结合提示词和有限文本模式，不能识别所有改写或保证法律事实正确。历史原文条款与施行日期可以解释，未联网确认效力时必须保留局限说明。新增测试覆盖无关经济文件、外地文件、标题 HTML、缺乏证据的效力断言及安全段落保留；真实在线效果仍需在用户网络环境复测。

### 联网分阶段诊断与同义表述修复

聊天响应新增 web_diagnostics：stage、search_count、official_count、extraction_requested、extraction_returned、body_count、accepted_count、rejected_counts 和 pages。界面可展开“联网过程”，查看搜索、正文提取和最终保留数量，以及每个允许范围内网页的未采用原因；被拒绝的不安全链接不返回前端。异常也保留中断阶段，不再将联网失败与零结果混为一谈。诊断对象按请求创建，不通过服务全局可变字段传递。

筛选识别津贴/补贴/补助的相关表述，仍需正文匹配养老及具体主题。杭州政府站点可为仅写“本市”的正文提供来源地区线索，但不等于自动认定条款对用户适用；其他地区或伪造相似域名不因此通过。现有启发式仍可能存在误筛，需结合展开的诊断复核。

单次搜索候选数扩大为 min(10, 最终条数×3)，批量提取这些候选再筛选，最终仍按 TAVILY_MAX_RESULTS 限制展示数（默认 3）。不增加搜索轮数，但正文提取 URL 更多，可能增加 Tavily 用量。被筛选之外的相关候选标记为 output_limit，不标为无关。

`python -m scripts.check_tavily` 同时输出分阶段计数、页面去留与原因；网络错误输出中断阶段。诊断不保存 API Key、聊天历史或网页正文，不额外持久化网页。当前环境仍不能访问 Tavily，真实问题的具体丢失环节需用新版界面或该命令复测。

### 政策类别与原文一致性辅助检查

新增 verify_grounding 节点，独立调用 Qwen 逐段审查政策类别及金额、年龄、地区、条件关系，程序再验证摘录来源与部分数字依据。未通过段落不展示；审查失败不放行草稿。响应新增 answer_checks 和 policy_categories。这是辅助检查，不能替代政策人工审核；当前调用次数、验收样例、已完成项及待办统一维护在 [政策顾问优化记录](政策顾问优化记录.md)。本次无需数据库迁移，重启后端和刷新前端生效。

固定业务评测已增加18条用例及报告脚本，当前仅完成数据集与工具校验，在线全量业务验收未完成。详见 [政策顾问评测说明](政策顾问评测说明.md)。

### 来源完整性边界与适用范围
