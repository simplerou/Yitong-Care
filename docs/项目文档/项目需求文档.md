## 1. 项目背景与目标

### 1.1 背景

- 社区居家养老是当前养老服务体系的主场景，老年人及其家属的高频诉求集中在**健康管理、用药安全、养老政策、膳食营养、跌倒防护、心理关怀**六类。
- 相关知识分散在政策文件、诊疗指南、药品说明书、社区服务手册中，老年人难以检索和理解；社区养老顾问人手有限，大量问题被重复回答。
- 大模型 + RAG 可以把"知识服务"规模化，但养老场景对**准确性、可追溯、隐私安全、适老化**的要求显著高于一般问答产品，必须做到"答案有出处、操作有反馈、风险有兜底"。

### 1.2 项目定位

面向社区居家养老的「智能体 + 知识库」服务门户：

- **对居民**：一个入口，用自然语言获得六类养老服务的解答，并能查看答案依据的原文。
- **对社区**：一套可运营的知识库与检索工具，把政策、指南沉淀为可检索资产，服务过程留痕可追溯。
- **对平台**：一个可扩展的智能体框架，新增业务只需新增配置 + 知识库，不必重写页面。

### 1.3 建设目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G1 | 统一服务入口 | 一个门户承载智能体、知识库、服务记录，菜单层级不超过两级 |
| G2 | 多业务智能体 | 至少 5 个，每个有独立业务定位、独立菜单、独立知识范围（本期 6 个） |
| G3 | RAG 全链路可运营 | 上传、切块、向量化、检索、结果查看五步均可由社区人员独立操作 |
| G4 | 答案可追溯 | 命中知识时，回答必须带引用编号，可一键查看原文、来源与字符位置 |
| G5 | 适老化可用 | 大字号、大按钮、低认知负担，支持长辈模式与键盘操作 |

### 1.4 成功衡量（试点阶段）

| 指标 | 目标值 | 验证方式 |
| --- | --- | --- |
| 上线智能体数量 | ≥ 5（本期 6） | 菜单与路由检查 |
| 有据可依率 | 命中知识时 100% 带引用 | 抽查 50 条问答 |
| 知识运营闭环耗时 | 单文档上传→可检索 ≤ 5 分钟 | 社区人员实操计时 |
| 检索响应 P95 | ≤ 500ms（不含生成） | 压测/埋点 |
| 首字返回 P95 | ≤ 2s | SSE 埋点 |
| 可用性测试任务完成率 | ≥ 80%（n ≥ 8，含 60 岁以上用户） |  moderated usability test |
| 服务满意度 | ≥ 4.0 / 5 | 回答后反馈按钮 |

## 2. 用户角色与权限

| 角色 | 典型用户 | 核心诉求 | v1 权限 | 优先级 |
| --- | --- | --- | --- | --- |
| 居民 / 老年人 | 60 岁以上社区老人 | 用大白话问健康、用药、政策；看清答案出处 | 智能体问答、原文查看、长辈模式 | P0 |
| 家属 | 子女 | 代老人提问、了解服务记录与提醒 | 问答、服务记录（需绑定） | P1 |
| 社区养老顾问 | 社区工作人员 | 维护知识库、检索验证、转人工跟进 | 文档/切块/向量/检索、服务记录 | P0 |
| 平台管理员 | 平台运营 | 模型与知识库配置、权限、审计、数据看板 | 全部 + 用户与权限 | P1 |
| 系统 | 后台任务 | 解析、向量化、索引重建、失败重试 | 服务账号 | P1 |

> 原型默认登录用户为"张阿姨（拱墅区·和睦社区）"，未实现登录与角色隔离。正式版必须在网关层完成鉴权，菜单按角色动态渲染，接口做数据级权限校验。

## 3. 项目范围

### 3.1 本期范围（P0）

1. Web 端门户（桌面优先，最小支持 1024px 宽）。
2. 6 个业务智能体：健康管家、用药管家、政策顾问、膳食营养师、安全守护、心灵陪伴。
3. RAG 全链路：文档上传、文本切块、向量入库、向量检索、检索结果与原文展示、检索记录。
4. 智能体调用 RAG 的问答闭环：检索状态、命中提示、流式回答、引用角标、来源面板、原文弹窗。
5. 知识库管理与文档状态流转。
6. 服务记录与检索留痕。
7. 长辈模式与基础无障碍。

### 3.2 本期不做（Out of Scope）

| 项 | 说明 | 后续版本 |
| --- | --- | --- |
| 原生 App / 小程序 | 本期只做 Web；移动端 H5 适配放二期 | P2 |
| 智能硬件接入 | 跌倒雷达、智能手环、紧急按钮 | P2 |
| 在线问诊 / 处方 / 医保支付 | 涉及医疗资质与支付合规 | 不纳入 |
| 120 / 急救调度对接 | 仅提供"拨打 120"提示，不做系统对接 | 视政策而定 |
| 多社区多租户 | 本期单社区演示 | P2 |
| 语音识别 / 方言 | 适老化重要，但需额外模型与硬件 | P1 评估 |
| 实时人工客服坐席 | 本期仅"转人工"工单草稿 | P1 |

## 4. 总体业务流程

### 4.1 居民服务流程

```
选择智能体 / 全局搜索
        │
        ▼
  输入自然语言问题
        │
        ▼
  查询理解（v1 直接检索，v2 增加改写）
        │
        ▼
  Embedding 语义召回（余弦过滤）+ BM25 关键词召回 + RRF 融合 + TopK
        │
        ├── 无命中 ──► 兜底话术 + 转人工入口
        │
        ▼
  组装上下文（片段 + 出处）──► 大模型流式生成
        │
        ▼
  回答 + 引用角标 ──► 点击角标 / 右侧参考知识 ──► 原文弹窗
        │
        ▼
  有帮助 / 需改进 / 重新生成 ──► 服务记录（留痕）
```

### 4.2 知识运营流程

```
上传文档 ──► 解析正文 ──► 文本切块（预览/保存）──► 向量入库（进度/日志）
                                                          │
                                                          ▼
                                                   检索验证（TopK/阈值）
                                                          │
                                                          ▼
                                                   发布 / 下线 / 重建索引
```

## 6. 交互与界面要求

### 6.1 菜单与路由

- 采用 SPA Hash 路由，菜单切换不整页刷新，切换后回到内容顶部。
- 路由与菜单同源：`path`、`title`、`icon`、`group`、`roles` 由一份配置生成。
- 当前菜单高亮 + 面包屑 + 浏览器标题同步。
- 从检索记录、服务记录跳转时，保留来源上下文（查询词、会话）。

### 6.2 操作反馈矩阵

| 动作 | 即时反馈 | 成功反馈 | 异常反馈 |
| --- | --- | --- | --- |
| 上传文档 | 拖拽高亮 / 解析中标签 | 文档数 +1、toast"解析完成" | 格式/大小错误提示（P1） |
| 切块 | 滑块实时改数字、预览刷新 | toast"已保存 N 段"、状态变"已切块" | 空文档提示 |
| 向量入库 | 进度条、批次日志、步骤状态 | 100%、集合统计更新、toast | 失败重试（P1） |
| 检索 | 按钮加载态 | 结果列表 + 命中数 + 耗时 | 空结果引导降低阈值 |
| 提问 | 检索中→命中 N 条→生成中 | 流式回答 + 引用 + 来源 | 无命中兜底 + 转人工 |
| 删除 | 二次确认弹窗 | 列表移除、统计更新、toast | — |
| 复制原文 | — | toast"已复制" | 手动选择提示 |
| 切换长辈模式 | 立即放大 | toast 提示 | — |

### 6.3 页面状态规范

- **加载**：按钮禁用/转圈，超过 300ms 才显示骨架，避免闪烁。
- **空状态**：图标 + 一句解释 + 下一步按钮（如"去切块"）。
- **错误**：说明原因 + 重试入口，不吞错误。
- **禁用**：置灰并说明原因（如未切块不能入库）。
- **确认**：删除、清空等不可逆操作必须二次确认。

### 6.4 适老化与无障碍

- 长辈模式：基础字号 14→16px，聊天 13.5→16px，按钮 38→44px，行高 1.85。
- 正文对比度 ≥ 4.5:1；不仅靠颜色传达状态（配文字标签）。
- 所有可点击元素有 hover/focus 态，Tab 可访问，Esc 关闭弹窗。
- 文案用大白话，避免"Embedding""TopK"等术语直接暴露给居民端（管理端可保留）。
- 关键路径不超过 3 次点击。

### 6.5 响应式与兼容

- 基准分辨率 1440×900，最小 1024×768。
- ≤ 1120px：对话页与检索配置区上下堆叠。
- ≤ 900px：侧边栏收为图标态（原型已支持）。
- 浏览器：Chrome / Edge 100+、Safari 15+；不支持 IE。

### 7.2 文档状态机

```
上传 → 解析中 → 已解析（待处理）
                  │
                  ▼
               已切块 ──重新切块──┐
                  │               │
                  ▼               │
               已入库 ────────────┘（旧向量失效）
                  │
                  └─ 删除 → 已删除（级联切块、embedding 与索引中的向量）
```

> "已入库"表示 MySQL 中的 embedding 已写入，且对应 FAISS 索引已更新。两者不一致时，以 MySQL 为准并触发索引重建。

### 7.3 数据保留与脱敏

- 服务记录建议保留 3 年，检索记录 1 年，具体以属地政策为准。
- 姓名、手机号、身份证号、健康指标属于敏感信息，列表与日志中脱敏展示。
- 删除文档时级联删除切块、embedding、FAISS 索引中的向量与引用关系，并记录审计日志。
- 训练/评测使用数据需去标识化，遵循《个人信息保护法》与医疗健康数据相关规定。

## 9. 接口与集成

**本期技术基线（已确认）**：后端 Python（FastAPI），大模型通义千问（Qwen，DashScope），MySQL 8.0 + FAISS（faiss-cpu）。MySQL 保存文档、文本块与 embedding BLOB，是唯一数据源；FAISS 以 `IndexIDMap2 + FlatIP` 建立派生索引，索引文件版本化落盘，可按知识库重建。

完整接口定义见《设计说明》第 6.3 节，核心接口如下：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/documents` | 上传文档并创建解析任务 |
| GET | `/api/documents` | 文档列表与状态 |
| POST | `/api/documents/{id}/chunks:preview` | 切块预览 |
| POST | `/api/documents/{id}/chunks` | 保存切块 |
| POST | `/api/documents/{id}/embeddings` | 触发向量化 |
| GET | `/api/embeddings/tasks/{id}` | 入库进度与日志 |
| GET | `/api/vector-index/status` | FAISS 索引状态（版本、条数、维度） |
| POST | `/api/vector-index/rebuild` | 从 MySQL 重建指定知识库索引 |
| POST | `/api/retrieval/search` | 向量检索 |
| GET | `/api/retrieval/logs` | 检索记录 |
| POST | `/api/agents/{id}/chat` | SSE 流式问答（含 citations） |
| GET | `/api/chunks/{id}` | 原文片段 |

问答响应中的引用结构：

```json
{
  "answer": "……【1】【2】",
  "citations": [
    {
      "index": 1,
      "chunk_id": "c_1024",
      "doc_id": "d3",
      "doc_name": "老年人跌倒干预技术指南",
      "source": "中国疾病预防控制中心",
      "seq": 1,
      "start": 0,
      "end": 218,
      "score": 0.032787,
      "text": "跌倒是我国65岁以上老年人伤害死亡的首位原因……"
    }
  ]
}
```

集成依赖：PDF/Word 解析服务、Embedding 服务（bge-m3 / bge-large-zh）、MySQL 8.0（业务数据 + embedding）、FAISS 索引、大模型（通义千问 Qwen，DashScope，SSE）、对象存储（MinIO）、缓存（Redis）。

- 空状态：无文档、无检索、无记录时均有引导文案与下一步按钮。

- 键盘：Tab 可遍历主要操作，Esc 可关闭弹窗。

### 10.3 非功能验收

- 检索 P95 ≤ 500ms、首字 P95 ≤ 2s（压测报告）。
- 权限：未登录/越权访问接口返回 401/403，菜单不可见。
- 安全：上传非法文件被拦截；回答内容经过 XSS 过滤。
- 兼容：1024/1440/1920 三档宽度无横向滚动、无遮挡。
- 索引：删除 FAISS 索引文件后可从 MySQL 全量重建；重建期间旧索引可读；索引条数与 MySQL 已向量化条数一致。
- 容量：按试点规模（约 5 千条向量）检索 P95 达标；20 万条以上需给出迁移或 HNSW 方案。

## 12. 假设、依赖与风险

### 12.1 假设

- 社区可提供可公开使用的政策、健康、膳食等知识文档，并授权入库。
- 试点环境可访问大模型与 Embedding 服务（公有云或私有化部署）。
- 首期用户以 60–80 岁社区老人及社区顾问为主，使用桌面或大屏设备。

### 12.2 依赖

- 文档解析与 OCR 能力（扫描版 PDF 需要 OCR）。
- MySQL、FAISS 索引与大模型服务的稳定性、配额与网络。
- 社区账号体系与组织架构（用于权限与转人工）。

### 12.3 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 模型幻觉 / 错误建议 | 健康与政策误导 | 强制引用、无命中不编造、医疗免责声明、人工兜底 |
| 政策时效性 | 引用过期文件 | 知识库版本与有效期字段、定期复核、下线机制 |
| 老年数字鸿沟 | 不会用、看不清 | 长辈模式、大按钮、社区协助、后续语音 |
| 数据隐私 | 健康信息泄露 | 最小化采集、脱敏、RBAC、审计、加密 |
| 文档解析质量差 | 切块与召回质量下降 | 上传后预览校对、OCR、失败重试 |
| 检索效果不达预期 | 答非所问 | 混合召回 + Rerank、评测集、阈值调优、badcase 闭环 |
| 依赖外部模型服务 | 超时/涨价/断供 | 多模型适配层、超时降级、私有化备选 |

### 检索实现更新（2026-10-28）

当前后端采用 Embedding + FAISS 语义召回、jieba 分词的 BM25 Okapi 关键词召回和 RRF 排名融合。MySQL 是文档、切块、向量及历史记录的唯一数据源；原有 FULLTEXT 索引保留，但当前召回不使用它。原型中的哈希/IDF 演示说明只对应冻结的浏览器原型。

两路均先限制知识范围、已完成文档、模型和维度；BM25 使用范围内全部合格切块统计词频，k1=1.5、b=0.75、IDF=ln(1+(N-df+0.5)/(df+0.5))，同一查询词计一次。每路最多 60 条，全局语义候选在各知识库召回后合并排序。RRF=Σ1/(60+rank)，排名从 1 开始，未召回贡献 0，按融合得分降序、块 ID 升序取 TopK。

API `threshold` 保留字段名与 0.02–0.6 范围（默认 0.12），新策略含义为语义余弦下限；BM25 不受该阈值过滤。`strategy=bm25_rrf`，`score` 为原始 RRF 分数，`bm25_score` 为原始 BM25 分数，另返回 `semantic_rank`、`bm25_rank`。两路命中时 RRF 理论最高为 2/61≈0.032787，不能当作概率或百分比。`lexical_score` 在新策略中等于原始 BM25 分数，保留供兼容。旧记录标记 `legacy_weighted`，保持原有分数与阈值含义，不重新计算。

更新需执行 `cd "Yitong Care/backend"` 后运行 `python -m alembic upgrade head`（迁移 0004）。无需重新向量化或重建 FAISS。当前 BM25 每次请求读取范围内切块并构建词频统计，尚无缓存/独立搜索服务，大规模使用前应压测并评估持久倒排索引；Rerank、查询改写及业务评测集仍待实现，不能据融合方式直接宣称效果提升。
