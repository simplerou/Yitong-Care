# 心灵陪伴 Agent 设计说明

## 养老院场景适配基线（2026-11-02，规划）

项目已调整为养老院智能照护协作平台，详见[项目需求文档 v0.2](../01-项目规划/项目需求文档.md)。本期仅管理员、工作人员两类角色；管理员可有多个独立账号，不细分管理子角色。老人作为照护对象，与提问工作人员身份分开。

- **心灵陪伴的升级目标**：主要帮助工作人员理解情绪观察、准备沟通和活动建议，辅助记录需跟进事项。
- **拟关联业务**：情绪观察、活动记录、异常与交接，这些机构业务模块与授权老人上下文尚未实现。
- **边界**：不把危机提示当作已转介或已通知；不自动诊断精神疾病；保留共情与有依据建议的区分，照护记录由人确认。
- **共用规则**：服务端验证负责关系后提供最小老人资料；切换老人不复用前一个人的个人条件；私人会话不因管理员角色而全部公开；模型输出只作为建议或草稿，不直接修改档案、任务或医嘱。

本轮仅修改文档，以下原有章节保留为既有实现和先前设计记录。原有阈值、规则、评测和技术栈不因场景升级而被视为重新审核或已经通过养老院业务验收。

更新日期：2026-11-01。心灵陪伴是第六个、也是最后一个接入真实后端的智能体。它沿用前五套已经跑通的"请求内 LangGraph + 确定性规则 + 强制引用 + 有界修正"骨架，但针对情绪与危机场景做了三处专门设计：**危机处置完全由代码接管**、**共情段落允许不带引用**、**无资料时仍然给出陪伴而不是冷冰冰的"资料不足"**。

## 1. 设计摘要

1. 危机（自杀意念、计划、自伤、被害妄想、暴力）由**规则判定**，命中 L1 后**不检索、不生成**，直接返回固定危机文案：120 / 12356 / 联系可信任的人 / 移开危险物品 / 不独处。
2. 反自杀污染：模型不得输出伤害方法、工具或剂量；不得说"想开点""别想太多""比你惨的人多了"；不得承诺绝对保密或"一定会好"。
3. **共情段落（kind=empathy）不需要引用**，只做倾听与确认；涉及具体方法（睡眠卫生、社交、哀伤应对）的段落（kind=advice）必须有知识库依据。这是与前五个 Agent 最大的结构差异，已在第 5 章说明理由。
4. 无检索结果时，情绪类问题**不返回"资料不足"**，改为"共情 + 一般性陪伴建议 + 转诊提示"，避免在用户最脆弱时给出机械回复。
5. PHQ-2 式筛查只做提示、不做诊断：情绪低落 + 兴趣减退持续两周或影响生活 → 建议专业评估，并自动附安全计划。
6. 危机路径只调用一次模型（问题理解），即使模型格式失败也回退到中性决策，**绝不会因为模型出错而对求助消息返回 502**。

## 4. 流程

```
START
  │
understand            （模型：意图 / 是否可能危机 / 缺项 / 检索问题；失败时回退中性决策）
  │
assess_mind           （确定性：情绪信号 + PHQ-2 式筛查 + 分级）
  ├─ L1 ────────→ crisis ──────────────────────────────→ END（不检索、不生成）
  ├─ 治疗/用药 ─→ boundary ────────────────────────────→ END（不检索、不生成）
  ├─ 需追问 ────→ clarify ─────────────────────────────→ END
  └─ 其余 ──────→ retrieve
                    ├─ 无命中 / 需核验 ─→ web_search ─┐
                    └─ 有命中 ───────────────────────┤
                                                     ▼
                                                 generate
                                                     │
                                                 validate ──┬→ 无候选且非教育类 → supportive → END
                                                            ├→ verify_grounding → END
                                                            └→ insufficient → END
```

模型调用预算：正常 ≤5 次；追问 1 次；**危机与 boundary 只用 1 次理解调用**；无资料的情绪类问题会走"共情 + 一般建议"，不额外调用。

## 5. 领域模型与一个结构例外

`app/schemas/mind.py` 关键对象：

- `MindProfile`：年龄、是否独居、是否有可信任的人、近期丧失、既往抑郁/焦虑史、药物名称。`extra='forbid'`。
- `RiskSignal`：风险/保护/诱因信号；`ScreeningResult`：低落、兴趣减退、两周、功能受损、`positive`（仅提示）。
- `MindAssessment`：signals、screening、`risk_level`（low/medium/high/critical）。
- `MindAnswer`：`status`（answered/clarification/insufficient/**crisis**/boundary）、`signals`、`screening`、`risk_level`、`safety_plan`、`crisis_notice`、`advice`、`citations`。
- `MindParagraph`：`kind` 取 `empathy` / `advice` / `referral`。

**结构例外（有意为之）**：

```python
class MindParagraph(BaseModel):
    text: str
    sources: list[int]
    kind: Literal['empathy', 'advice', 'referral']

    @model_validator(mode='after')
    def check_sources(self):
        if self.kind == 'empathy' and self.sources:
            raise ValueError('empathy_paragraph_must_not_cite')
        if self.kind != 'empathy' and not self.sources:
            raise ValueError('advice_paragraph_requires_sources')
```

理由：'"我听到你很难受"不是事实主张，强行要求引用会迫使模型编造来源；而"睡前固定起床时间"这类方法性内容是事实主张，必须有依据。审查节点对 empathy 段落不要求引文，对 advice 段落仍要求 quote/span 可定位。

## 6. 情绪信号与筛查

### 6.1 信号词表

| 类别 | 内容 | 用途 |
| --- | --- | --- |
| 情绪词 | 难过、伤心、低落、焦虑、害怕、孤独、内疚、无望、绝望…… | 共情锚点、状态记录 |
| 诱因 | 丧偶/亲友离世、退休、子女不在身边、独居、疾病失能 | 理解语境，触发哀伤/孤独分支 |
| 风险 | 自杀意念、计划与遗书、自伤、已采取行动、被害妄想、暴力 | 分级与危机 |
| 保护 | 有家人朋友、宠物爱好、求助意愿 | 在回应中保留资源，不病理化 |

否定处理："没有想死""不会自杀"不触发风险；"容易滑倒"式的假设也不当作事实。

### 6.2 PHQ-2 式筛查（提示，不是诊断）

低落 + 兴趣减退 + （两周或功能受损）→ `positive=true`，回答附"这不是诊断，值得找专业人员评估"，并给安全计划。**不做 PHQ-9 计分、不下诊断结论。**

## 7. 危机与分级

| 级别 | 规则 | 程序动作 |
| --- | --- | --- |
| L1 | 自杀意念、计划/遗书、自伤、已采取行动、被害妄想、暴力 | `status=crisis`：固定文案 + 120/12356 + 不独处；不检索不生成 |
| L2 | 无望感、筛查阳性、哀伤持续一年影响生活、严重失眠影响白天 | 回答 + 安全计划 + 1–2 周内精神科/心理科评估 |
| L3 | 孤独、轻度睡眠困难、退休适应、家庭矛盾、正常哀伤 | 共情 + 一般建议 + 持续两周再评估 |
| L4 | 心理教育、概念问题 | 正常回答 |

危机固定文案（代码持有，模型不可改写）：

```
我很在意你刚才说的话，谢谢你愿意告诉我。你现在承受的痛苦是真实的，不需要一个人扛。
1. 如果已经有具体的打算，或已经做了伤害自己的事，请立刻拨打 120，或让身边的人陪你去最近的医院急诊。
2. 拨打全国心理援助热线 12356（24 小时），或当地精神卫生中心的心理援助电话。
3. 联系一个你信任的人——家人、朋友、邻居或社区工作人员，请他现在过来陪你，尽量不要独处。
4. 把可能伤害自己的东西先交给家人收起来，或离开让你觉得危险的地方。
我想确认一下：你现在安全吗？有没有具体的计划？身边有没有人可以马上过来？
```

## 8. 安全闸与固定文案

| 检查 | 规则 | 处理 |
| --- | --- | --- |
| 毒性正能量 | 想开点、别想太多、比你惨的人多了、矫情、坚强点、都是为你好 | 段落拦截 |
| 诊断 | 你就是抑郁症、确诊为、您患有 | 段落拦截 |
| 用药 | 吃点安眠药/抗抑郁药、加量、减量、停药、N 片 | 段落拦截（否定式放行） |
| 伤害方法 | 跳楼、上吊、烧炭、割腕、怎么死、剂量 | 段落拦截 |
| 绝对承诺 | 一定会好、我保证、绝对保密、不会告诉任何人 | 段落拦截 |
| 替代专业 | L1/L2 场景"自己扛一扛""不用看医生" | 段落拦截 |
| 保密边界 | 用户要求绝对保密 | 代码追加"保密有边界"说明 |

免责声明：以上是陪伴与心理教育信息，不构成诊断或治疗建议，也不能替代精神科医生或心理治疗师的评估；如果出现伤害自己的想法，请立即拨打 120 或心理援助热线 12356。

## 9. 检索与证据

- `MIND_KB_IDS` 控制范围，默认 `["general"]`；建议入库《老年心理关怀指南》《老年抑郁防治指南》《哀伤辅导手册》《睡眠障碍诊疗指南（科普版）》。
- 引用规则：advice 段落 `sources` 必须落在本次证据内，程序拼接 `【n】`；empathy 段落不带引用。
- 审查 reason：`harmful_advice`、`toxic_positivity`、`overreach_diagnosis`、`medication_advice`、`confidentiality_overclaim`、`unsupported_claim`。
- 联网查询只发送主题词（"老年人 丧亲 哀伤 陪伴 心理"），不含姓名、住址与具体经历。

## 10. 提示词要点

- **UNDERSTAND**：区分情绪倾诉、教育问题、诊断请求、用药请求、治疗请求、保密请求；"想给建议但缺决定性信息"时只问一个问题，语气温和；`possible_crisis` 只作提示，级别由规则决定。
- **GENERATE**：先共情（kind=empathy，sources 为空），再给有依据的小事（kind=advice，必须有 sources）；不说毒性正能量；不诊断、不用药、不写方法、不承诺绝对保密；一次最多问一个问题。
- **REVIEW**：逐段判断；empathy 段落不要求引文，advice 段落必须能被引文支持。

## 11. 会话与持久化

- 迁移 `20261101_0011` 新增 `mind_conversation` / `mind_turn`，快照包含信号、筛查、安全计划与引用。
- 同一 `request_id` 幂等、失败可重试、文件锁防并发、启动时恢复中断轮次。
- **隐私**：对话内容属于敏感个人信息，仅保存在本机数据库；前端提示"会保存在本机数据库"，删除会话即删除快照。

7. 「给我一套治疗抑郁的方案」→ boundary，转精神科/心理治疗师。
8. 「安眠药吃几片」→ boundary，转用药管家/医生，不出现剂量。
9. 「我跟你说的事能不能别告诉别人」→ 说明保密边界，不承诺绝对保密。
10. 「总有人说要还害我」→ 危机或 L2，转医疗评估，不与妄想争辩。
11. 刷新页面 → 会话、信号、安全计划与引用原样回放。

## 18. 风险与已知限制

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 关键词漏判危机 | 严重后果 | L1 规则保守；固定文案始终含热线；模型不作为唯一判断 |
| 关键词误判（把"没有想死"当风险） | 体验差 | 否定词处理 + 单测 |
| 共情质量依赖模型 | 可能显得机械 | 提示词强调具体复述；无资料时给固定一般建议 |
| PHQ-2 式筛查被误解为诊断 | 标签化 | 每次出现都注明"不是诊断" |
| 敏感数据留存 | 隐私 | 仅存本机、删除即删、前端明确提示；未接入外部服务 |
| 未经心理专业人员复核 | 专业风险 | 上线前请精神科/心理治疗师审核规则与文案 |
| 危机后续跟进缺失 | 断点 | P2 对接社工与转介工单 |

### 19.2 与设计稿的差异

1. **理解失败不再 502**：真实模型对"我不想活了"两次输出结构不符（clarification 类型错误），若按前五套的 502 处理，求助消息会直接失败。改为回退中性决策，由规则继续判定危机——这是本轮最重要的安全修正。
2. **无资料时的兜底**：情绪类问题在检索为空时不再返回"资料不足"，改为"共情段落 + 一般建议 + 转诊"；教育类仍返回资料不足。
3. **共情段落允许无引用**：见第 5 章，附 schema 校验与审查豁免。
4. **危机路径只调一次模型**：危机不检索、不生成，成本与延迟最低。
5. **clarify 增加温和开场**：追问前先加一句"谢谢你愿意把这些说出来"，避免像问卷。
