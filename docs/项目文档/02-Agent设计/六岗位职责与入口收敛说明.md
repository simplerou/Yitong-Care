# 六岗位职责与入口收敛说明

更新：2026-11-12。本说明是当前岗位职责、页面入口和接口权限的依据；与历史规划冲突时以本说明为准。

## 当前六类 Agent

Supervisor 是内部调度，不作为第七个业务岗位。根据服务端身份卡，LangGraph 条件边把请求交给对应岗位流程；用户和模型都不能自行指定另一个身份。

| 岗位 | 页面职责 | 与其他岗位的联系 |
| --- | --- | --- |
| 院长 | 运营看板、审批台、员工注册审核与账号启停 | 核对专业校验结论、医生签字状态与成本，批准用药、配餐、排班及核薪草稿；不建档、不分配护工、不读取病历明细 |
| 医务室 | 用药助手、用药草稿、结构化医护资料核实、异常待办 | ReAct 查档案和说明书、代码校验、生成草稿；医生签字后交院长；处理护工异常待办 |
| 食堂 | 菜单助手、菜单与换餐审批、备餐清单 | ReAct 使用脱敏约束、食物目录及 HowToCook；配餐交院长，护工换餐由食堂复验批准；不接收病历和药品标识 |
| 护理部 | 护工账号与老人分配、老人建档维护、排班助手、已批准排班、照护审核 | 只从已通过注册审核的护工中分配；排班交院长，照护上报由护理部审核 |
| 财务部 | 工时核对、代码核薪、核薪草稿与工资解释 | 代码计算工时和金额，模型可解释；不能修改排班或打卡，核薪单交院长 |
| 护工 | 负责老人、只读档案与餐食、打卡、执行清单、异常上报、换餐校验 | 仅负责范围；不能编辑档案和处方或直接改套餐；换餐必须校验后交食堂 |

公开注册仍为五类员工岗位申请，院长账号不开放注册。护理部不授予账号岗位、不审核注册；它管理已开通护工的负责关系。医务室和护理部要求有效任职资质，过期时接口拒绝专业操作。

## 业务连接

- 用药：医务室查证 → 独立规则校验 → 医生签字 → 院长审批 → 护工执行与记录。
- 配餐：医务室核实资料 → 后台生成脱敏约束 → 食堂生成并校验配餐草稿 → 院长审批 → 食堂备餐。
- 换餐：护工选择负责老人并提出方案 → 后台读取当前资料校验 → 食堂看到匿名方案并复验批准 → 食堂确认备餐 → 护工执行确认。
- 照护：护工上报 → 护理部审核；同时进入医务室异常待办。医务室标记已处理不代替护理部审核，也不自动开药。
- 排班与核薪：护理部排班草稿 → 院长审批 → 护工打卡 → 财务代码核薪与解释 → 院长审批。

护工上报和换餐校验使用确定性流程，不让模型修改输入、决定冲突是否成立或自动审批。配餐当前仍是**带服务日期的一日方案**，不是自动发布七天三餐周菜单。历史周菜单只读资料保留；新协作执行单不自动改写历史套餐选择。

## 旧咨询功能处理

健康管家、用药管家、政策顾问、膳食营养师、安全守护、心灵陪伴不再作为可访问的业务 Agent。移除侧栏入口、前端路由和正常服务 `/api/agents/*` 接口；旧地址返回工作台，旧 API 返回404。

知识库、RAG管理、原周菜单编排/发布、老人自助绑定、原审计及修正管理页面不再开放为岗位入口，对应维护接口从正常 API 撤下。历史源码、数据表、文档和资料没有删除；内部说明书检索、FAISS/BM25/RRF、HowToCook 等底层服务继续供岗位流程使用。

历史回归测试可通过 Python 工厂参数 `create_app(legacy_compatibility=True)` 构建旧接口。正式 ASGI 入口 `app.main:app` 默认关闭；没有 HTTP 或前端开关。该模式用于历史回归，不应作为正式部署入口。新增岗位边界测试显式关闭兼容模式。

## 权限与验收

前端按岗位白名单生成导航、可访问路由和工作台标签；后端单独校验账号状态、岗位、资质、负责范围和工具权限，隐藏按钮不是权限保障。护理部独占护工清单、建档维护及分配接口，院长和护工均不能调用这些写入接口。

专项测试 `backend/tests/api/test_six_role_product.py` 覆盖正常服务旧接口下线、护理部建档分配、院长/财务隔离、护工只读、换餐校验到执行、照护与临床处理分离以及资质过期阻断。历史回归还保留旧 RAG/咨询测试，不能将历史兼容测试等同于新产品接口开放。

本轮不新增数据库迁移，不删除或调整现有账号、老人或历史记录。仍需在本机完成既有迁移、真实 MySQL、Neo4j、模型与浏览器联调；自动测试使用 SQLite 和虚构规则，不代表临床验收。

验证记录：后端全量 628 项通过；前端 99 项 Vitest 与 4 项 Node 测试通过，生产构建通过。新增 5 项严格产品模式测试，历史接口回归通过独立兼容模式执行。未完成真实 MySQL、Neo4j、模型和浏览器联调。

## 工作台导航（2026-11-13）

六类岗位统一使用左侧业务菜单切换模块。右侧撤下重复的模块按钮，只显示当前模块名称；模块和护工任务同步到地址栏，刷新及浏览器前进后退保持对应模块，生成草稿和编辑草稿时同步左侧选中项。护工增加“申请记录”侧栏入口，保留查看上报与换餐申请的入口。注册审核内部的“申请与账号 / 审核记录”仍为该功能内部分类。
