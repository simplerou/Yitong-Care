# 岗位Agent职责与ReAct调用说明

更新：2026-11-12。岗位范围及入口以[六岗位职责与入口收敛说明](六岗位职责与入口收敛说明.md)为准；本文补充 ReAct、医生签字和调用约束。

| 角色 | 调整前 | 当前实现 |
| --- | --- | --- |
| Supervisor | 按任务字段选择子图 | StateGraph读取服务器身份卡，经条件边路由到岗位；不分析临床问题，也不接受模型提供身份 |
| 医务室 | 固定步骤查证、代码校验、模型整理说明 | 原生Function Calling + LangGraph ReAct；只读查证/代码校验/局部暂存草稿；医生签字后才交院长审批 |
| 食堂 | 固定步骤和结构化输入 | 受限ReAct；工具参数严格Pydantic校验；患者/药品标识没有入口，只见脱敏约束、目录与营养结果 |
| 护工 | 可以编辑老人资料、选/改套餐、提交换餐草稿 | 执行清单、记录（完成/打卡）、上报、换餐校验与申请；资料和原套餐只读，换餐需食堂批准 |
| 院长Agent | 审批时看到完整草稿和证据 | 三个工具：看校验、看成本、审批；协作审批API不返回病历、药品、剂量、患者身份和专业修改正文 |

## Supervisor

自然语言入口先通过 `operations/supervisor.py` 的身份卡路由，再进入岗位ReAct子图；结构化入口也按身份卡路由。医生问状态仍进入医务室，不会根据问题内容转成另一个岗位。未知身份默认拒绝。家属账号/视图目前没有基础，本轮不新增家属角色。

自然语言医务室入口由用户先选择老人，服务器绑定目标；模型工具不能随意提交另一位老人ID。食堂自然语言入口的Schema只有text字段，携带resident_id等额外字段直接拒绝。

## 真正的ReAct与Function Calling

新增 `operations/react.py`，调用模型API的真实 `tools / tool_choice` 参数，不再让模型用普通JSON假装选择工具。每轮为“模型选择函数 → 服务器验证函数和参数 → 执行受限工具 → 将结构化观察交回模型”。

- 医务室模型工具：read_record、drug_evidence、validate_medication、medication_draft、review_draft。
- 食堂模型工具：constraints、food_catalog、recipe_search、nutrition_check、menu_draft、review_draft。
- medication_draft/menu_draft仅在请求内部暂存候选，不直接写入医嘱、签字、审批或执行。
- 每次调用重新检查岗位和资质；额外参数、未注册函数、跨域查询被拒绝。
- 最多9轮模型交互、8次工具调用、2次工具纠错；共享180秒预算。预算耗尽或独立校验服务不可用时不生成草稿。
- 单位mg/g保留原始量，再由Decimal代码转换为mg。名称有歧义或药品事实未核实就停止，不补造药品标识。
- 固定方案模式不允许模型改变人工指定的药品剂量/频次、食物量或服务日期；模型可解释结果，方案和判定仍由代码约束。
- 只查询状态时，查证后可以返回答复而不创建草稿。状态工具区分在用药资料、已审批记录和待确认草稿，不能把“草稿已准备”说成“已开药”。

自然语言入口：`POST /api/operations/assistant/medical`、`POST /api/operations/assistant/kitchen`。工作台“自然语言需求”可使用；结构化表单继续保留。

配餐结构仍沿用当前的一日完整方案及服务日期；原七天三餐数据保留为历史资料，管理入口已撤下。本轮没有把一日方案伪称为已完成七天菜单，也没有自动改写已发布周菜单。

## 医生签字与院长审批

```text
查档案 / 说明书 → 规则校验 → 暂存候选 → 代码复校 → 用药草稿
    → 医生检查原文、单位、剂量、过敏并填写意见签字
    → 院长只看校验结论、专业已签字状态与成本
    → 再验权限、资质、草稿版本/时效、来源和规则
    → 院长审批 → 按批准方案生成护工执行清单
```

`POST /api/operations/drafts/{id}/sign`只允许原医务室作者以有效资质签字。签字绑定草稿版本、内容哈希、源指纹及规则/图事实哈希。修改草稿清除签字，不能沿用旧签字批准。执行前也拒绝没有有效医生签字的用药单。

此处“签字”为已登录专业人员的确认留痕，不宣称法律意义的数字证书签名。模型没有签字、审批或发药工具。

院长审批视图的当前方案、原始方案、临床引用和详细轨迹被脱敏；临床审计及修正正文也不通过该视图返回。成本取登记单价，药品按mg×次数、食物按克数/100计算一日估算；缺单价显示待核实，不把未知当0，也不从模型文字采用“50元”。

**权限口径**：正常服务中院长只进入看板、审批与注册审核，不能访问老人档案、护工分配、知识库管理。历史兼容模式仅用于回归，不作为正式入口。

## 护工异常上报到医务室

护工不再编辑档案、照护资料或直接改套餐；可申请换餐，经代码校验交食堂批准。查看负责老人、餐食和执行说明仍按负责关系授权。

提交日常/紧急上报后，服务器在同一事务保存上报及医务室待办，不等待模型处理，不自动开药。护理部负责照护审核，医务室工作台提供“异常待办”，可以核实并填写处理记录。只在应用内部投递，不向外部邮件、微信或短信发送消息。紧急情况仍需立即联系现场值班医护，网页待办不替代应急处置。

医务室标记已处理不会自动生成处方或用药执行单；若确需调整用药，另走查证、校验、医生签字与审批流程。

## 医疗事实说明

“服华法林忌绿叶菜”不能作为一刀切的禁用规则。饮食限制需要有效资料和专业人员核实的个体依据，涉及维生素K摄入等问题应按医生指导处理，不能让模型将示例转成未经核实的临床规则。
