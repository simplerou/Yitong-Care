## 基准和范围

基准为用户上传的《杭州市民政局 杭州市财政局关于健全高龄及困难老年人补贴制度的通知》（杭民发〔2024〕142号）。已从原始PDF提取逐页文本，保存PDF哈希和文本哈希；用例中的摘录可回查页码。此基准只代表指定文件原文，不证明其现行效力。

代码仓库中的可共享评测文件：

- `backend/evaluations/policy/cases.json`：18条固定用例、预期状态、文本锚点、原文页码、摘录及人工检查清单。
- `backend/evaluations/policy/reference.txt`：带页码的基准文本，不是新的知识库入库记录。
- `backend/app/evaluation/policy.py`：校验数据集、机械断言、生成报告。
- `backend/scripts/evaluate_policy.py`：真实调用现有服务层，无需先启动API服务器。

16个本地用例覆盖政策概览、年龄分档、金额和发放周期、地区边界、困难家庭、护理待遇、比例下限、基本生活补助、电子积分、代申请、叠加/互斥、长护险衔接、必要追问、多轮追问及未知下载链接。2个联网用例覆盖最新政策和142号文件现行效力。

## 运行方法

在项目的 backend 目录、agent_env 环境中运行。先确认基准PDF已完成解析、切块和当前模型向量入库，且政策顾问知识范围包含该文档。

```bash
# 不连接数据库、不请求模型：检查基准哈希、摘录、ID和正则
python -m scripts.evaluate_policy --validate-only

# 执行16条本地用例，调用真实Qwen和Embedding，但主动禁用联网
python -m scripts.evaluate_policy

# 执行全部18条：本地用例仍隔离联网，仅2条联网用例使用Tavily
python -m scripts.evaluate_policy --web

# 先跑少量用例；--case可以重复
python -m scripts.evaluate_policy --case P02 --case P03
python -m scripts.evaluate_policy --web --case W01
```

这是会消耗模型和搜索服务额度的真实评测，顺序执行，不并发。检索会沿用现有逻辑写入检索日志，不自动导入、删除或重新向量化文档。多轮用例使用本次真实返回的前文，不能用预先写好的理想回答代替。

本地评测主动关闭联网，即使用户实际配置了Tavily也不会调用；由此产生的“联网未配置”提示是隔离方式的结果，不代表实际Key丢失，不应作为本地问答的事实错误。

## 报告与判断

每次生成独立目录：`backend/var/evaluations/<UTC时间>-<随机标识>/`，内有 `report.json` 和 `report.md`。默认位置已被 `.gitignore` 忽略，不提交完整回答和来源快照。

JSON保留数据集及原文哈希、代码文件哈希、Git版本/脏状态、模型与Embedding标识、知识范围、文档内容哈希和索引版本、每轮问题/完整回答/原文引用、检查结果、错误和耗时。不读取或写出API Key、数据库密码及`.env`全文。报告包含知识库原文，应按项目数据管理要求保存在本地。

机械检查包括预期回答状态、关键文本锚点、召回锚点、引用编号与来源位置、回答辅助检查是否完成、联网是否触发及常见无依据时效表述。它们不是语义事实评分：例如答案同时提到40元和100元，不代表两档年龄对应正确；正则也可能将反驳错误金额的句子误判。因此自动失败应结合原文核对，自动通过也必须人工审核。

- automated_pass：机械断言全部通过，人工仍待审核。
- automated_fail：至少一个机械断言失败；不等于已经人工确认政策事实错误。
- blocked：基础服务或审查服务出错，本条无法正常评测。
- not_run：尚未调用本条，包括预检阻塞或前序服务错误导致停止。

运行整体可为 completed、partial 或 blocked；completed只表示所选执行流程完成，不表示人工验收通过。数据库、模型配置和基准文号/可用向量预检失败时，未调用的用例保留not_run，不计成错误回答。无Tavily配置时联网用例blocked。错误消息隐藏数据库连接细节，后续用例不会因同一基础服务异常重复调用。

在Markdown报告中逐项填写“通过／失败／无法判断”，注明证据、问题类别及失败原因。回看JSON中的原文和引用，必要时查看原PDF，不能只信Agent自己的answer_checks。人工结论不自动回写JSON，也未做跨报告准确率统计；需要汇总时应明确区分人工标注与机械检查。

重点检查：政策类别有没有混淆；金额、周期与年龄/地区/困难条件是否正确绑定；没有捏造办理材料、网址；未联网确认时不宣称最新或现行有效；未把有条件叠加写成无条件同时领取。
