## 养老院角色口径（2026-11-02）

本期产品保留一种管理员角色，可配置多个管理员账号；工作人员暂不继续细分岗位权限。当前代码的 `user` / 普通用户是现有技术角色，升级目标是管理员开通或审核后的院内工作人员，不代表任意公开注册账号已经获得养老院业务授权。

老人作为独立照护档案，不作为登录账号；家属和老人端暂不纳入。管理员共享本院管理职责，不自动共享私人咨询会话。员工准入、停用、老人负责关系、正式照护任务和交接班仍是规划，本轮不修改账号代码、不执行数据库迁移，也不重新归档测试数据。

详细新需求以[项目需求文档](../01-项目规划/项目需求文档.md)和[升级实施清单](../01-项目规划/养老院升级实施清单.md)为准；下文保留现有账号功能及初始化操作说明。

## 权限

| 能力 | 普通用户 | 管理员 |
| --- | --- | --- |
| 六个智能体及个人会话 | 可用 | 可用 |
| 使用知识库支持的智能问答 | 可用 | 可用 |
| 知识库管理、切块、向量入库、手动检索、检索记录 | 禁止 | 可用 |
| 今日守护、最近对话 | 个人提醒与本人真实会话 | 演示提醒与本人真实会话 |
| 旧的工作台演示数据、服务记录演示页 | 隐藏 | 可见 |
| 其他账号的会话、进度、删除与修改 | 禁止 | 禁止 |

公开注册固定创建普通用户；客户端传入 role 不会授予管理员权限。管理接口返回 403，前端隐藏菜单并限制直接地址访问。管理员角色由服务端数据库决定，下一次请求立即采用更新后的角色。

## 数据安排

- 历史文档、切块、向量和检索日志保留原位，由管理员管理，避免复制数据或破坏 FAISS 与 MySQL 的关联。普通用户通过智能体检索使用这些知识；知识内容并非仅供管理员回答。
- 六个 Agent 的会话表增加 owner_id，新会话自动绑定当前账号。历史无归属会话默认不向任何登录账号展示，使用下方初始化命令归到指定管理员。
- 归档只更新 owner_id 为空的历史会话，保留原始轮次和回答快照，不调用模型，不移动向量，不删除数据，不覆盖其他用户的归属；重复执行不会重复归档。
- 原型内置的健康分、待办、张阿姨资料与演示服务记录只在管理员工作台展示。它们仍是前端演示数据，不是注册用户的真实健康记录。
- 登录与退出会刷新应用，清理当前页面内的聊天状态；六个 Agent 的本地会话选择按账号 ID 分开保存。

## 初始化管理员（在 backend 目录执行）

```bash
conda activate agent_env
alembic upgrade head
python -m scripts.setup_admin --claim-legacy
```

按提示输入管理员手机号。若账号已注册，提升为管理员并保留原密码；若账号未注册，交互设置密码，密码不回显、不进入命令行参数。没有内置管理员、默认密码，也没有自动将第一个注册用户提升为管理员。

执行后重启后端，重新登录。管理员应能看到旧会话和知识库入口，另注册普通用户应只看到自己的会话和智能体入口。当前工具环境无法连接用户本机 MySQL，本轮未实际执行迁移或归档；上述命令完成后才会在实际数据库生效。

## 验证

覆盖普通注册不能提权、普通用户管理接口返回 403、六个 Agent 跨账号列表/详情/删除隔离、历史归档幂等且不覆盖其他账号，以及前端管理路由限制。前端构建通过。账号认证仍为基础版本，未含短信验证、密码找回和登录限流。
