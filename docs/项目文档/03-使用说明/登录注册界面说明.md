# 登录注册与访问控制说明

## 养老院角色口径（2026-11-02）

本期产品保留一种管理员角色，可配置多个管理员账号；工作人员暂不继续细分岗位权限。当前代码的 `user` / 普通用户是现有技术角色，升级目标是管理员开通或审核后的院内工作人员，不代表任意公开注册账号已经获得养老院业务授权。

老人作为独立照护档案，不作为登录账号；家属和老人端暂不纳入。管理员共享本院管理职责，不自动共享私人咨询会话。员工准入、停用、老人负责关系、正式照护任务和交接班仍是规划，本轮不修改账号代码、不执行数据库迁移，也不重新归档测试数据。

详细新需求以[项目需求文档](../01-项目规划/项目需求文档.md)和[升级实施清单](../01-项目规划/养老院升级实施清单.md)为准；下文保留现有账号功能及初始化操作说明。

## 页面和认证

- 根地址默认进入 `/#/login`，注册页为 `/#/register`，移除未登录“返回首页”入口。
- 功能页导航前请求 `/api/auth/me` 校验服务端会话，未登录或凭证失效返回登录页；业务接口返回 401 时也返回登录页。
- 登录和注册接通后端真实接口，注册成功后需登录，业务顶栏提供退出登录。
- 密码经随机盐 scrypt 哈希存储；随机登录凭证只在数据库保存 SHA-256 摘要，会话有效期 8 小时，退出时服务端撤销凭证。
- 浏览器使用 sessionStorage 保存登录凭证，不保存密码；关闭标签页后需重新登录。
- 登录、注册及服务健康检查公开，其余现有 `/api` 业务接口要求有效登录。前端路由限制不能替代后端校验。

## 启用

在 `Yitong Care/backend` 下激活 agent_env，执行：

```bash
conda activate agent_env
alembic upgrade head
```

新增迁移 `20261101_0012` 创建 `account`、`login_session` 表。重启后端并刷新前端，再注册新账号测试。当前工具环境连接本机 MySQL 被系统限制，迁移尚需在用户终端执行；SQLite 接口回归不代表本机 MySQL 已完成迁移。

批量导入脚本现在也需要登录，将有效登录凭证通过 `YITONG_AUTH_TOKEN` 环境变量提供，不要写入代码或提交到 Git。
