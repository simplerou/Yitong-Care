# 员工注册与岗位审核说明

> 2026-11-12 当前入口与权限请先阅读[六岗位职责与入口收敛说明](../02-Agent设计/六岗位职责与入口收敛说明.md)。旧六类咨询已撤下；护工分配归护理部；护工换餐须校验和食堂审批。以下旧流程如有冲突属于历史记录。


更新：2026-11-12。本说明取代此前“注册后直接成为可用护工”的流程；既有账号无需重新审核。

## 员工流程

1. 在注册页填写真实姓名、手机号、密码，选择申请岗位：护工、医务室、食堂、护理部或财务部，可补充入职说明。
2. 提交后自动登录并进入“岗位申请状态”，此时只可查看自己的申请、刷新状态或退出，不能访问业务数据。选择岗位不等于获得权限，不能自注册院长。
3. 院长通过后，原申请会话失效。员工重新登录，进入实际授予岗位的工作台。
4. 未通过时重新登录可查看原因，调整岗位或补充说明后重新提交；不必用另一个手机号重复注册。
5. 护工即使审核通过，仍须由管理员分配负责老人，才能查看相应档案。

## 院长操作

入口：工作台顶部“注册审核”，或左侧“运营管理 → 注册审核与账号状态”。

- 默认列表为待审核，可切换未通过、已开通、已停用，支持分页。
- 选择申请，线下核对姓名、手机号提示和任职信息。可以调整实际授予岗位。
- 医务室和护理部必须填写资质/任职核实记录与有效期，过期资质不能开通专业岗位。
- 未通过必须填写原因。审核、重新申请及状态调整均保留审计记录。
- 已开通账号的岗位调整继续在“岗位协作 → 岗位与资质”进行；未审核账号不能通过该旧入口绕过注册审核。
- 离职时选择已开通账号，填写原因后停用。停用会删除登录会话并禁止登录；恢复后需重新登录，专业资质仍须有效。
- 最后一位有效院长不能被停用或撤销。院长身份不开放公开注册，仍由可信后台流程创建和管理。

## 后端权限与状态

公开注册显式写入 `status=pending` 和 `requested_role`，实际角色在审批前保持普通占位角色，不拥有业务权限。业务统一依赖只允许 `active` 的身份检查；待审核和未通过账号只有认证、自己的申请状态、未通过后重新申请、退出等有限接口可用。前端隐藏菜单之外，直接请求业务API同样被拦截。

状态为 pending（待审核）、rejected（未通过）、active（已开通）和 disabled（已停用）。申请、审核及账号状态修改使用版本字段，过期页面不能覆盖新结果；重复同结果审核不会重复写权限。通过或未通过审核时删除原登录会话，防止申请令牌直接升级为业务令牌。

接口：

- `POST /api/auth/register`：接收姓名、手机号、密码、申请岗位和说明，不能自授状态/实际角色。
- `GET /api/auth/me`：允许未审核账号读取自己的申请状态。
- `PUT /api/auth/application`：仅未通过申请可按当前版本重新提交。
- `GET /api/account-reviews`：院长按状态分页查看账号。
- `POST /api/account-reviews/{id}/decision`：院长核实后通过或未通过。
- `PUT /api/account-reviews/{id}/status`：院长停用/恢复已开通账号。

所有业务端的护工候选、负责关系分配及岗位授权只接受已开通人员。

## 清空旧账号重新开始

这是受信任的本地维护操作，不提供网页入口。会清除包括院长在内的所有可登录账号、会话、申请资料、资质、老人负责/绑定关系，撤回旧待确认草稿并取消待执行清单。老人档案、知识库、向量和业务历史保留。档案版本会随负责关系解除而更新，原饮食/医护依据需要重新核实。

无业务外键引用的账号直接删除；需要保留历史引用的账号清空姓名、手机号、密码和权限，变成不可登录的匿名占位记录，不出现在注册审核及岗位人员名单。原手机号可重新注册；账号快照中的显式姓名和手机号提示也匿名处理，不按字符串误删老人姓名或其他业务正文。

```bash
# backend，agent_env 环境；默认仅预览
python -m scripts.reset_accounts
# 明确清空全部可登录账号
python -m scripts.reset_accounts --apply
# 重新创建院长；不要自动认领旧会话
python -m scripts.setup_admin --name 院长
```

脚本单事务提交，失败则回滚，不关闭外键约束。当前执行环境实际运行因数据库连接失败未清理，需在本机数据库可连接时执行。关联清理、匿名快照、回滚预览、手机号重用及审批/排班外键保留已通过测试。

## 注册审核记录（2026-11-13）

院长进入“注册审核”，切换“审核记录”。可按全部、已通过、未通过筛选，按审核时间从新到旧分页查看申请人、脱敏手机号、申请岗位、实际授予岗位、审核人、北京时间和意见；展开可查看申请说明、任职核实记录及资质有效期。

同一账号被退回后重新申请，每次审核分别保留。重复提交同一审核不会新增重复记录；账号后续停用或恢复不会改变原审核结果。新审核保存当时的申请及人员名称快照，避免后续资料变动覆盖历史。旧事件缺少快照时显示现有姓名或历史占位，缺少的申请说明和版本不补造；没有审核事件的历史账号不会凭当前“已开通”状态伪造审核记录。

接口 `GET /api/account-reviews/history` 仅院长可访问，支持 `result=all/approve/reject`、`page` 和 `page_size`。基于已有审核事件，无需新增迁移。账号启停仍在“申请与账号”处理，审核记录只读。
