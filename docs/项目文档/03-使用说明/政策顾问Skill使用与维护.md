# 政策顾问 Skill 使用与维护

更新日期：2026-11-05。

## 已实现的运行方式

政策顾问现在固定使用项目内 `eldercare-policy` Skill，版本 `1.0.0`。这是后端业务规则资源，不是安装在 Codex 全局目录的开发技能，也不是由用户输入自由选择的插件。

无需填写 API Key、安装新依赖或配置新工具。部署此次代码后重启后端，再向政策顾问提问即可；业务规则已由模型调用路径实际加载，而不只是新增说明文件。

## 文件位置

从仓库根目录查看：

```text
backend/app/skills/eldercare-policy/
├── SKILL.md                         # 名称、版本、适用范围与阶段说明
└── references/
    ├── query-analysis.md            # 问题理解、条件继承、必要追问
    └── evidence-answer.md           # 地区、时效、金额、证据与部分回答
```

- `backend/app/services/policy_skill.py`：读取固定资源，校验基础格式并计算内容指纹。
- `backend/app/services/chat/prompt_builder.py`：保留程序控制的 JSON 契约与输入安全边界，组合当前阶段的 Skill 内容。
- `backend/app/agents/orchestrator.py`：每次请求取得一份快照，理解、生成和格式重试使用同一份规则。

理解阶段加载入口与咨询理解规则；生成阶段加载入口与证据解读规则。参考文件由后端实际读取，不依赖模型自行访问文件。原来的业务规则已从长提示词常量迁出，保留了既有多轮、年龄分档、地区边界及部分回答的特殊处理要求，并去除完全重复的规则段落。

## 职责划分

Skill 负责业务处理规范：范围识别、不重复追问、不擅自扩展问题、政策类别区分、地区适用、时效说明、保留金额限定与有依据的部分回答。

代码继续负责：账号权限、LangGraph 路由、RAG 检索、Tavily 调用、超时与重试上限、JSON 结构、引用编号、年龄和金额校验、原文一致性复核，以及会话保存。事实资料仍来自每次请求的原文证据，不来自 Skill 中的例子。

本阶段没有实现模型自由挑选多个 Skill 或自动执行 Skill 脚本。用药管家仍为 RAG + Tavily；菜单的 HowToCook 不受影响。

## 如何更新规则

1. 根据需要修改 `query-analysis.md` 或 `evidence-answer.md`，避免重复写入程序已经执行的校验。
2. 修改 `SKILL.md` 的 `metadata.version`，使用三段版本，例如 `1.0.1`。
3. 运行相应政策测试，再以完整版本部署规则文件，避免线上逐个编辑时混用不同版本。

后端不缓存全局提示词，每个新请求读取已部署文件；请求建立快照后，期间的文件更新不会改变其后续阶段。规则文件缺失、空白、版本格式错误等情况返回明确的 503，不静默使用旧提示词或无规则生成。

Skill 内容仍会成为模型提示的一部分；迁移的价值是集中维护与版本追踪，不保证自动降低 Token 或提高模型准确率。

## 如何确认加载

- `/api/agents/policy/config` 返回 `skill`：名称、版本、SHA-256 指纹。
- 本次问答的响应也包含 `skill`，并随历史回答快照保存。
- 后端日志记录名称、版本和指纹，不记录完整业务提示或用户原文。
- 旧问答没有 Skill 元数据时返回 `null`，不将当前版本冒充为旧回答使用的版本。

相同版本文件被改动时，内容指纹仍会变化；正式更新请同时提升版本号。用户界面不增加内部规则配置入口。

## 验证与人工测试

```bash
# 在 backend 目录
python -m pytest tests/unit/test_policy_skill.py tests/test_policy_graph.py tests/api/test_policy_conversations.py -q
```

本轮包含 Skill 阶段加载、资源异常、下一请求更新、同一请求版本一致、历史元数据回放，以及安装包资源加载验证。接口测试使用模拟模型，不等于线上政策事实或 Qwen 行为已验证。

可人工验证：

- “杭州市的养老补贴有哪些？”——已有地区时先检索概述，不先追问个人年龄。
- 同会话问“那90岁呢？”——继承用户原先明确的地区和类别，不重复询问。
- “温州市龙湾区长护险有哪些服务项目？只找到部分也先说明。”——只解释有原文支持的部分，不拿其他地区标准填补。
- “这个文件现在还有效吗？”——区分文件规定与是否完成现行效力核验，不因未搜到废止就认定有效。

验证记录：后端全量575项测试通过，最终规则复核后专项38项通过，前端TypeScript与生产构建通过；Skill格式验证与安装包资源加载验证通过。未调用线上模型重新评测。
