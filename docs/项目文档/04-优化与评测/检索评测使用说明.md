# 检索评测使用说明

更新：2026-11-17。用于对照简历中的检索效果指标，评测粒度为chunk；不修改RAG流程或数据库。

## 输入格式

两份JSONL分别提供独立标注与待测系统导出的排序，`id`逐条对应且唯一。先对query独立标注相关chunk，再固定索引、模型及检索参数运行系统并导出结果；不要向检索器提供真值。示例：

```json
{"id":"query-001","split":"holdout","query":"已独立标注的问题","relevant_chunk_ids":[12,35]}
```

```json
{"id":"query-001","retrieved_chunk_ids":[77,12,35]}
```

块ID可以是整数或字符串，内部统一成字符串；重复块或重复query id拒绝。相关集合不能空；无答案问题应建立另一个专门的拒答评测。空检索数组是有效失败，缺失query的检索结果标为blocked，两者不混淆。校准集仅用于调参；保留集不要用于反复选参。

## 运行

在backend目录：

```bash
python -m scripts.evaluate_retrieval --labels /path/to/labels.jsonl --rankings /path/to/rankings.jsonl --split holdout --k 10
```

报告默认写入 `backend/var/evaluations`，不提交GitHub。输出macro Recall@K、micro Recall@K、MRR@K、HitRate@K及计分/阻塞样本数。macro Recall是每个问题相关块召回比例的平均；micro Recall是总命中相关块数除以总标注相关块数；MRR取前K中第一个相关块名次的倒数；HitRate为至少命中一个相关块的问题比例。分母只包含有检索结果记录的计分样本；必须同时报告blocked和complete，完整性不足时命令返回非零，不将局部得分当作全量结论。

格式自检示例：

```bash
python -m scripts.evaluate_retrieval --labels evaluations/retrieval/example-labels.jsonl --rankings evaluations/retrieval/example-rankings.jsonl
```

虚构保留样例有2个相关块，只返回其中1个，因此Recall@10为0.5；这仅证明计算示例可运行，不是项目真实召回率。当前工具仅评分已提供排序，不宣称自动执行了线上FAISS/BM25/RRF。真实评测需自行固定并记录模型、向量维度、索引和语料版本、阈值及RRF配置后导出排序。
