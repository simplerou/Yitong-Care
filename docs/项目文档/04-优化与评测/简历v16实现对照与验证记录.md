# 简历 v16 实现对照与优化记录

更新：2026-11-17。依据《赖关瑞-简历-AI应用开发-v16.pdf》项目一“禾龄通”；不包含项目二青禾训练助理。只对照技术和业务能力，不将个人分工、团队规模、工作经历或历史成果数字视为可以从代码验证的事实。

## 当前结论

六岗位身份路由、专业 ReAct、独立图谱规则校验、草稿—签字—审批—执行及岗位隔离已经形成主线。此次补齐人工修正复盘入口、三路回流统计、原生工具调用质量统计和检索指标评测，并修复草稿修订后的风险等级同步问题。功能实现基本对应项目一的描述；真实业务部署、临床事实核实和简历成果数字仍需独立验收。

## 本次新增与修复

### 草稿内人工修正与复盘

在各自草稿详情下提供“人工修正与复盘”。原提交人员可查看原因、修改前后方案并填写复盘结论；重复闭环幂等。结论留在审计事件中，不自动改写图规则、提示词或模型，不把标记闭环视为已完成模型训练。

新增接口 `GET /api/operations/drafts/{id}/feedback`、`POST /api/operations/feedback/{id}/resolve`。使用原有草稿权限和资质检查。院长、其他审批岗位只见脱敏修正类别、标签与状态，不能查看专业修改正文或代为关闭；跨岗位无权对象统一404。

修改事件额外保存前后校验快照、草稿版本和源指纹，保留规则与图事实指纹。页面展示版本变化；仅原临床作者可见完整临床校验内容。精确重放旧事实仍要求另行保留相应版本图事实，不能仅凭一个哈希恢复数据。

### 风险等级同步

修订草稿时以新校验结果更新风险等级，清除医生旧签字，并追加人工复校轨迹；修订升级到风险3时不能沿用旧风险等级绕过必填审批意见。

### 院长看板与统计

新增近30天原生 ReAct 成功、失败、拒绝数量及有效调用成功率；只读服务调用保持单列。分母为“工具已注册、严格Schema与岗位权限通过后实际发起的调用”，拒绝不混入分母。已知外部服务失败在请求终止前记录；日志不存工具入参、原始模型上下文或患者资料。数据库无法写审计的故障不在已记录样本内，不能宣称是所有生产请求的完整指标。

周/月汇总新增规则核对、Agent改进、培训三路的新增、待复盘、已闭环数量。批准/原样采纳/人工覆盖按批准事件时间归属统计；修正按创建时间分组，闭环为这些修正的当前状态，不表示该周期发生的关闭事件数。旧数据无批准事件时不补造历史审批时间。

### 检索评测

新增 `scripts/evaluate_retrieval.py`。详见[检索评测使用说明](检索评测使用说明.md)。工具对独立标注与实际检索排序评分，默认只评测holdout，不调用模型、不改数据库、不从检索结果自动生成真值。

## 验证与实际环境

本轮验证结果见文末。自动测试使用SQLite、测试传输及虚构事实，覆盖权限、工具协议、闭环幂等、脱敏、风险同步及统计计算。示例检索输入是手工构造的格式样例，得分不代表真实检索效果。

当前工具环境MySQL连接仍失败。没有执行真实数据库迁移或修改真实账号、老人及临床资料；真实Neo4j、MCP、模型服务和浏览器逐项交互仍待联调。此次复用已有Correction/Event表，无新增迁移；使用前需完成既有 `alembic upgrade head`，重启后端并刷新前端。

## 不伪造简历成果

- Recall@10约85%：需固定语料版本、标注范围、混合检索参数与索引版本，使用独立相关块标注复测。
- 工具成功率约95%：需在明确的有效请求分母和时间窗口采集足量实际调用，不能用测试通过率替代。
- 节时约30%：需同任务、同人工复核标准的配对人工基线与辅助流程计时；本轮未进行此研究。
- 当前人工待确认通过MySQL业务状态持久化和确认接口续接，不将其宣称为LangGraph原生checkpointer/interrupt恢复。
- 不把技术栈或岗位模拟当作生产部署、临床验收、真实团队经历或历史业务成果的证据。
