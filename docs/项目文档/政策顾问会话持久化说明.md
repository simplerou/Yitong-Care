# 政策顾问会话持久化与快照回放

更新日期：2026-10-29。

## 使用方式

需先在 backend 目录、agent_env 环境执行：

```bash
python -m alembic upgrade head
```

新增迁移 `20261029_0005`，创建 `policy_conversation` 和 `policy_turn` 两表。随后重启后端，刷新前端政策顾问页面。无需重新入库、向量化或重建FAISS。

页面可新建、选择、删除历史会话，支持分页载入更多会话和更早问答。首次发送时若未选择会话，自动新建。会话标题取首个问题前60字，不额外调用模型。浏览器只记住所选会话ID，问答和依据来自MySQL；刷新或重新进入页面会恢复历史。

每条历史答案有“查看本次依据”，右侧切换到对应轮次的保存快照。点击本地引用查看保存片段；点击网页引用查看保存的网页正文，另有“打开官网当前页面”入口。当前官网可能变化，不能把当前页面当成历史快照。回放仅读取数据库，不调用Qwen、Embedding或Tavily，不重新核验政策时效。

## 数据和接口

`policy_conversation` 保存UUID、标题及UTC创建/更新时间。`policy_turn` 保存请求UUID、会话ID、顺序、原问题、运行状态、尝试次数、最终PolicyAnswer JSON、错误摘要及UTC时间。

快照包含答案、引用、检索片段、网页正文/URL/日期/完整性元数据、模型名称、知识范围、检索记录ID、步骤、审查状态及问题代码。它没有文档、切块或检索日志的外键依赖，所以这些原数据删除/重切块后仍可核对当时依据。快照不是整个原PDF或完整网站副本，仅覆盖当次传给模型并返回的片段。删除会话会级联删除其问答及快照，不删除知识库和已有检索记录。

| 方法 | 接口 | 行为 |
|---|---|---|
| GET | `/api/agents/policy/conversations?page=1&page_size=20` | 分页会话列表 |
| POST | `/api/agents/policy/conversations` | 新建空会话，返回201 |
| GET | `/api/agents/policy/conversations/{id}?before_seq=...&page_size=20` | 读取最新或更早问答及快照，不调用模型 |
| DELETE | `/api/agents/policy/conversations/{id}` | 删除会话与快照 |
| POST | `/api/agents/policy/conversations/{id}/turns` | 提问或显式重试 |

提问示例：

```json
{"request_id":"客户端生成的UUID","question":"杭州的高龄补贴标准是什么？","retry":false}
```

服务端从同会话、该问题之前最近3条完成记录构建6条user/assistant历史；失败和运行中记录不作为模型答案历史。客户端不能上传history覆盖数据库历史。原 `/api/agents/policy/chat` 无状态接口保留兼容，不自动保存会话；业务评测脚本仍走服务层，不会把评测用例写成真实用户会话。

## 去重、并发与异常

- 一轮完成返回的状态包括answered、clarification和insufficient，均保存PolicyAnswer，轮次状态记为succeeded（只表示请求完成，不代表答案正确）。
- 相同会话+请求UUID+问题若已保存成功，重复POST直接返回原快照，不再次调用模型。相同UUID换问题/换会话返回409。
- 请求先保存running，再执行模型流程，最终保存快照；服务异常保存failed和安全错误摘要。无返回对象的异常不保存未经审查的草稿。
- 失败记录默认重复POST只回放失败，必须`retry=true`才重新执行。只能重试最后一条失败记录，避免改写已有后续上下文；新问题可以跳过失败记录继续提问。
- 单机会话文件锁贯穿生成与保存，避免同一会话跨进程并发写入；新提问、重试或删除遇到活跃写入返回409。不同会话不共享此锁。
- 刷新或前端请求超时后，先读取数据库核对状态。服务器仍运行时前端轮询读取；已成功则回放，避免盲目再次付费调用。保存状态不明时重试仍使用原请求UUID。
- OS进程退出会释放锁。读取会话时在确认无写者后将遗留running标记为中断失败，允许显式重试；不冒充已完成或自动恢复模型调用。读取恢复前清除旧事务快照，避免将刚完成的MySQL记录误判为中断。
- 文件锁文件位于 `backend/var/conversation_locks`，不删除正在使用的锁文件。当前仅适用于单机多进程；多机部署需改为可靠的分布式/数据库任务协调。

不保证外部模型计费的exactly-once：如果模型已响应但进程在保存前崩溃，显式重试可能再次产生费用。已保存的成功快照不会重算。离开页面仅取消前端等待，不保证终止后端已开始的请求。

## 验证与边界

自动测试覆盖：新建/列表/分页、来源删除后回放、请求去重、服务器历史、失败显式重试、旧失败不可插回历史、跨会话UUID冲突、活跃写锁、崩溃中断恢复和敏感异常不保存；前端覆盖刷新恢复、旧请求不覆盖新会话、超时核对、同ID重试及轮询读取。

当前环境真实MySQL迁移尝试返回OperationalError，未完成在线数据库升级。迁移MySQL离线SQL成功生成；隔离SQLite测试不能代替真实MySQL迁移及并发验收。浏览器控制工具未获准访问Chrome，未完成实机界面检查。

当前无登录/RBAC，会话沿用现有管理端访问边界，不代表已实现用户隔离。仅政策顾问接入本功能，其余Agent仍为演示。首页和服务质量演示统计尚未改为真实聊天统计。尚无LangGraph checkpointer、后台队列、自动保存中途草稿、独立结构化用户画像或会话导出。

升级后此前仅在页面内存中的旧问答无法追溯恢复；新问答开始保存。快照体积随问答数量增长，分页避免一次加载全部，但尚未实现压缩、归档或保留期限策略。

本轮最终验证：后端160项、前端26项软件测试通过，TypeScript检查及Vite构建通过，MySQL迁移离线SQL生成成功。真实迁移尝试因OperationalError未执行成功；浏览器控制未获准访问Chrome，未完成实机界面验收。这些测试结果不等同于真实数据库已升级。
